# ADR-0252 — Мітка візиту на нитку живе в базі

- **Статус:** Accepted
- **Дата:** 2026-10-12
- **Замінює:** у ADR-0251 пункт 10 — мітку візиту в `localStorage`
- **Зачіпає:** `supabase/migrations/20261012120000_memory_visits.sql`
  (нова таблиця `memory_visits`), `src/types/index.ts`
  (`MemoryVisitRow`), `src/features/memories/useSeenSince.ts`
- **Не зачіпає:** решту таблиць, правило підсвітки
  (`unseenFromPartner`), інші модулі
- **Вказівка власника (2026-10-12):** «Додай таблицю в базу, щоб зникала
  функція нових фото» — переглянуте «нове» має гаснути на всіх пристроях.

## Рішення

1. Таблиця `public.memory_visits (user_id PK → users, couple_id, seen_at)`
   — один рядок на людину.
2. Доступ — той самий набір, що на кожній таблиці пари (`auth_only` +
   `couple_scope`), плюс `own_row`: людина читає й пише лише СВІЙ рядок.
   Партнерові не треба знати, коли ти заходив. Видалення не надано.
3. `useSeenSince` спершу читає попередню мітку з бази, лише потім пише
   теперішню (`upsert`). Помилка читання — без підсвітки й без запису,
   щоб не погасити «нове», якого людина не бачила.
4. Мітка, що лишилась у `localStorage` від ADR-0251, переноситься один
   раз і прибирається після успішного запису в базу.

## Наслідки

- Міграцію застосовано до проєкту «Amore» 2026-10-12 через Supabase MCP;
  перевірено три політики на таблиці, порадник безпеки нових зауважень
  про неї не дав.
- У розробці `StrictMode` запускає ефект двічі, і другий прохід читає вже
  записане «щойно» — у dev-збірці підсвітки може не бути. У продакшн-збірці
  ефект один.
