# ADR-0213 — Колода «Що наступне?» гортається свайпом

- **Статус:** Accepted
- **Дата:** 2026-09-27
- **Зачіпає:** `features/plans/PlanIdeaDeck.tsx`, `ideaDeckSwipe.ts` (новий,
  + тест), `plansFocus.css`, `plansModule.test.ts`,
  `scripts/live/{options,portal,shot}.mjs` (+ `options.test.mjs`),
  `docs/MODULE_STATUS.md`
- **Тип зміни:** взаємодія екрана «Плани»; модель даних не змінюється
- **Вказівка власника:** «Зроби, щоб у планах "що наступне" свайпалось вверх
  переходом на наступний план, а свайп вниз — на попередній, каруселлю, і
  прибери кнопку "далі", текст на кнопці "дати дату" зміни на "запланувати"»

## Рішення

- **Свайп угору — наступний задум, униз — попередній, по колу.** Картка йде
  за пальцем з опором, на відпусканні або гортається (понад 22% висоти
  картки чи різкий кидок у тому ж напрямку), або повертається на місце.
  Гортання — виліт картки в бік свайпу й в'їзд наступної з протилежного
  боку, 240 мс; під зменшеним рухом (§47) картка просто змінюється.
- **«Далі» прибрано**, головна дія — **«Запланувати»** на всю ширину.
- Після свайпу відпускання над кнопкою чи назвою не є кліком.
- Клавіатура: картка фокусується, ↓ — наступний, ↑ — попередній; лічильник
  «2 з 5» оголошується (`aria-live`).

Рішення «гортати чи ні» — чиста функція `deckMove` під тестом.

## Ціна, названа прямо

Вертикальний свайп і прокрутка сторінки — один рух пальця. На самій картці
вертикаль належить колоді (`touch-action: pan-x`), тож сторінка гортається
пальцем над карткою або під нею, а не по ній.

## Перевірено

Живцем (`npm run live -- plans --drag=.pf-card--swipe:-160 …` — оснастка
отримала `--drag`): угору 1 → 2 → 3, униз 3 → 2, кнопка «Запланувати»,
«Далі» немає. Відчуття свайпу на телефоні пісочниця не показує (пастка №7).
