# Amore — покращення модуля «Графік»

## Мета

Перетворити технічну таблицю робочих змін на зрозумілий інструмент для пари, який одразу відповідає на три запитання:

1. Коли ми обоє найближчим часом вільні?
2. Які спільні дні вже мають плани?
3. Як швидко оновити власний графік?

## Етап 1 — оновлення основного UX

Статус: **реалізовано**.

- [x] Додати повноцінну шапку модуля в стилі Pink Portal.
- [x] Показувати картку найближчого спільного вихідного та відлік до нього.
- [x] Додати компактну статистику спільних і персональних вихідних за місяць.
- [x] Зробити календарні клітинки інтерактивними.
- [x] Показувати на клітинках індикатор запропонованого або підтвердженого побачення.
- [x] Додати нижню картку з деталями вибраного дня.
- [x] Дозволити почати планування побачення з конкретного спільного вихідного.
- [x] Замінити дві календарні дошки редагування одним календарем із перемикачем партнера.
- [x] Додати список трьох найближчих спільних вихідних.
- [x] Зберегти поточну модель даних і realtime-синхронізацію без міграцій БД.

## Критерії приймання етапу 1

- На мобільному екрані календар не має горизонтального скролу.
- Найближчий спільний вихідний видно без пошуку в сітці.
- Натискання на будь-яку дату відкриває зрозумілий опис зайнятості.
- Запропоноване й підтверджене побачення візуально відрізняються.
- У режимі редагування однозначно зрозуміло, чий графік змінюється.
- Наявні сценарії підтвердження та видалення побачень продовжують працювати.

## Етап 2 — швидке введення графіка

- [ ] Додати явний вибір стану: «Робота», «Вихідний», «Не вказано».
- [ ] Додати режим масового позначення кількох дат.
- [ ] Додати шаблони «2 через 2», «3 через 3», «Пн–Пт».
- [ ] Додати копіювання графіка попереднього місяця.
- [ ] Показувати прогрес заповнення графіка кожного партнера.

## Етап 3 — часткова зайнятість

Потребує окремого рішення щодо моделі даних.

- [ ] Підтримати робочі часові проміжки, а не лише статус цілого дня.
- [ ] Визначати спільний вільний час увечері після роботи.
- [ ] Пропонувати часові вікна для побачень.
- [ ] Враховувати події основного календаря під час пошуку вільного часу.

## Технічні обмеження

- Поточний етап не змінює таблицю `work_schedule`.
- Статуси залишаються сумісними з наявним циклом `'' → Р → Х → ''`.
- Список спільних вихідних продовжує формуватися з двох позначок `Х`.
- Побачення використовують наявні статуси `pending` і `confirmed`.
